# 项目情况与优化路线

评估日期：2026-10-20。对象为当前本地 BoothNest Desktop 源码与原 Windows 发布包。

## 判断

项目已经具有实用的单用户桌面功能：只读扫描、压缩包线索、商品匹配、图文看板、筛选排序、统计与 CSV 导出。模块划分基本合理，Python 标准库后端和系统浏览器界面适合继续迭代，暂不需要重写为网站、Electron 或多用户服务。

原状态更接近作者自用工具。公开发布前的问题集中在首次体验、个人数据隔离、本机接口边界、异常时的数据可信度与可重复构建，而非缺少更多图表。

## 本轮处理的实际问题

| 问题 | 检查依据 | 处理 |
| --- | --- | --- |
| 发布包附带作者真实库 | 原 seed 含 848 条目、432 商品，发布包中内容完全一致 | 移除打包入口和自动播种；空白首次使用 |
| 目录选择在冻结包失效 | API 导入 tkinter，spec 排除 tkinter；原 exe 模块归档也不含它 | Windows 原生目录对话框 |
| 接口缺少访问凭证 | 任意白名单方法可通过 GET/POST 调用，无 Host/Origin 检查 | 会话令牌、同源校验、POST 和 JSON 限制 |
| 下载文件被直接 Shell 打开 | reveal_item 调用 os.startfile，且未限制根目录 | 仅对当前库存条目定位文件；目录可打开 |
| 取消后可能覆盖结果 | 名称反查循环 break，主流程继续组装并保存 | InterruptedError 传播；提交前再检查 |
| 扫描漏深层文件且吞错 | MAXDEPTH=4，listdir/文件异常被跳过 | 默认完整遍历、取消检查、警告及链接策略 |
| 缓存误用 | 指纹只有压缩包数和总大小；无根目录、mtime | 加入绝对路径、文件名、大小和纳秒时间 |
| 网络失败被永久视作下架 | verify 将任意空结果写 __notfound__ | 失败不持久化，识别旧负缓存，增加 TTL |
| 重启丢失界面设置 | 随机端口改变 localStorage 的 origin | 保存至本机 config.json |
| 窗口关闭后后台残留 | 冻结包验收时另一个已安装实例的同名窗口被算入存活窗口 | 当前界面的心跳与关闭通知，不影响其他实例 |
| 导出与统计容易误导 | 空 ID 数组被转为 None；多份同 ID 算可回收 | 空筛选保留空集合；改为待人工核对 |
| 缺少公开工程入口 | 构建命令绑定本机运行时、依赖无声明、无 CI | 统一入口、版本、合成测试、构建与源码打包 |

原文件访问与识别主要保持只读；这一点应继续作为产品约束。原库存、旧程序包、历史诊断脚本保留在开发者本机，提交与构建使用明确的排除 / 允许规则。

## 功能完善（1.1.0 Beta 2）

识别管理已支持搜索、状态筛选、分页、单条和批量操作、识别依据与 CSV 导出。人工规则独立保存，支持绑定 ID / 链接、取消归属、标记非商品和恢复自动识别。规则优先于自动结果，完整刷新与缓存清理不会覆盖，按扫描根和相对路径隔离。离线缺元数据仍可查看本地详情。

文件内容核对已支持按大小分组后流式 SHA-256、进度、取消、变化 / 无权限 / 链接警告、硬链接额外路径计数和 CSV 导出。结果不会触发删除。刷新目录后旧核对失效，取消保留上次成功结果。

尚未实现跨目录改名后的稳定条目 ID、手动规则迁移、文件版本语义比对或 NAS 专项性能优化。哈希核对的额外逻辑大小不等于物理磁盘可释放空间。

## 后续优先级

1. **修正与规则迁移。** 当前已能恢复自动归属；后续增加操作历史、规则导入 / 导出和路径迁移，提供更完整的人工纠错记录。
2. **版本语义核对。** 当前 SHA-256 能找出同内容文件；后续区分适配角色、版本、源文件与可共用资源，增加压缩包目录差异比对。保持不自动删除。
3. **多目录与库迁移。** 支持多个下载根、排除目录、NAS 断线后保留旧条目并标记离线、目录重定位。采用稳定条目 ID，与相对路径分离。
4. **大库性能。** 用合成 1,000 / 10,000 商品库测首屏、搜索、内存与扫描耗时。再决定 SQLite/FTS、目录变化监听、表格虚拟滚动，避免无基准重写。当前「增量」仍需目录遍历。
5. **网络和图片体验。** 增加明确的限流 / 403 / 离线状态、可重试图片、请求队列、缓存容量上限和按类型清理。当前缓存没有自动磁盘配额。
6. **识别覆盖。** 六位旧 ID、复杂目录分组、更多适配角色、模型和插件名别名；用有人工真值的匿名语料衡量准确率和误识别率。单个作者库的识别数量不能当作总体准确率。
7. **长期发布维护。** Windows 10/11、非管理员、中日文和含空格用户目录、多种浏览器的人工验收；后续加入代码签名、版本更新检查与升级回滚。默认不引入云账号或遥测。

## 本轮验证

- 原有 42 项发布回归测试与新增 17 项功能回归测试通过，覆盖本机接口、路径限制、取消、扫描、缓存、导出和生命周期；匹配、schema、真实 JavaScript 搜索 / 排序及界面语法检查通过。
- 实际 Edge 界面通过空白引导、中文及含空格路径的离线扫描、零结果筛选导出、跨端口偏好恢复检查，无运行时 JavaScript 错误。
- 实际 Windows 冻结程序通过空白首次启动、版本与冻结状态、原生目录选择器和正常关闭后的后台退出验收；测试使用独立临时数据与浏览器配置，不修改开发者已安装实例。
- Beta 2 的实际浏览器操作验证覆盖批量手动绑定、全量刷新保留、标记非商品、重载页面恢复、恢复自动结果、无元数据本地详情及 SHA-256 核对和导出，无运行时 JavaScript 错误。
- 发布程序与对应源码使用显式文件清单打包，排除个人库存和缓存，生成 SHA-256 与逐文件摘要。源码 ZIP 独立解压后执行同一套检查。

## 公开测试的边界

本轮自动检查用于验证合成目录、API、状态与数据处理；它们不能证明每种 Windows 环境都能运行，也不等同于实际 BOOTH 网络、图片 CDN、NAS 或真实商品的接受度测试。新发布包应先作为 Beta 发给少量用户，收集首次扫描、误识别与安装问题后再扩大范围。

向 GitHub 提交前可以检查 `.gitignore` 与构建产物清单。不要把旧 dist、seed、data、缓存、导出或历史截图加入仓库；这些文件保留在本机不会影响源码提交。不要为了演示默认加载真实用户库存。
