# 旧数据兼容与升级

本次只升级网站程序。发行包不附数据，不要求重新扫描或重新导入商品目录。新安装使用空库；已有安装沿用原来的数据目录。

## 兼容范围

| 已有数据 | 支持方式 | 升级时保留 |
| --- | --- | --- |
| BoothNest 现有网站数据 | 直接读取原目录，不用发行包初始化覆盖 | 整个网站数据目录，包括 `catalog.json`、`purchases.json`、`web-preferences.json`、`media/`、本地库连接、人工修正及任务配置 |
| BoothNest / BoothShelf 库存快照 | 读取 `data/dataset.json`，以实际关联条目展示本地商品；兼容旧 `bytes` 与现有 `size` 字段 | 整个引擎数据目录，包括 `config.json`、`data/`、`cache/`、`export/`；人工规则位于 `data/manual_overrides.json` |
| 自行保留的可选元数据索引 | 只读使用原索引，不随程序升级下载或替换 | 原索引文件、挂载路径、`BOOTH_NEST_OPEN_DATA`（若已设置）及来源许可说明 |

这里的兼容范围是 BoothNest / BoothShelf 已支持的数据格式，不代表可以直接导入任意 VRCatalogue 应用数据库、账号或浏览器配置，也不保证损坏文件或未来版本格式可用。`purchases.json`、商品目录和本地库存是不同用途的数据，不能互相覆盖。

## 更新已有网站 / fnOS

1. 停止旧服务，备份整个数据目录及原 `.env`、Compose、挂载与自定义环境变量，保留可回退的程序或镜像。
2. 将新版程序解压到独立目录；保留原来的数据卷和路径。Docker 可重新构建镜像，但必须沿用原卷映射。不要把新包的空目录覆盖到旧数据上，也不要使用 `docker compose down -v` 删除卷。
3. 沿用原 `BOOTH_NEST_WEB_HOME` 和 `BOOTH_NEST_ENGINE_HOME`。网站目录默认是网站程序旁的 `data/`；Docker 模板中，容器的 `/data/BoothShelf/web` 是网站数据目录，`/data/BoothShelf` 是引擎目录。主机上的实际目录以原 Compose 为准。
4. 保留登录、允许访问的域名、只读下载目录和已有索引挂载。自定义 Docker 构建上下文或索引路径的旧部署应继续沿用这些设置。
5. 启动后先核对库存条目、本地商品、收藏、购买记录、图片和经典管理页。核对时使用相同的内容评级与筛选条件；无需点击扫描、同步或导入。

全新目录的自动扫描和同步默认关闭。旧目录中已启用的任务会按原设置继续运行；需要保持数据快照不变时，升级前先在界面关闭这些任务。日常收藏、人工修正、扫描和同步属于正常写入操作，不是程序升级必需步骤。

回退程序时继续使用现有数据卷；恢复旧数据备份会丢失备份之后的修改，应单独决定是否需要恢复数据。

## 接入旧 Windows 桌面库存

先关闭旧应用并备份其设置页显示的数据目录。通常为 `%LOCALAPPDATA%\BoothNest` 或旧版 `%LOCALAPPDATA%\BoothShelf`；有自定义路径时以实际位置为准。

如果只想先浏览旧库存，可在本机网站连接旧库目录或 `data/dataset.json` 的绝对路径。库存快照只读关联，旧库不会因连接操作被重新扫描。

需要新版网站接管扫描和经典管理时，建议先复制一份旧库供新版使用，避免两个版本同时写入。以下示例中的 `D:\BoothNestData` 是你已复制好的引擎数据目录，应包含 `config.json` 和 `data/dataset.json`；不要把下载文件目录当作引擎目录：

```powershell
# 在解压后的网站程序目录执行；这两项路径位于同一份数据备份下，但用途不同。
$env:BOOTH_NEST_ENGINE_HOME = 'D:\BoothNestData'
$env:BOOTH_NEST_WEB_HOME = 'D:\BoothNestData\web'
node server.mjs
```

`BOOTH_NEST_HOME` 是旧桌面引擎的变量；网站使用上面的两个变量区分网站数据和库存数据。`BOOTH_NEST_PYTHON` 可指定 Python 3.12+ 解释器的绝对路径。首次建立新的网站目录时，原桌面库存会显示为本地商品，但不会凭空生成收藏、购买记录或发现目录。

在 Windows 和 fnOS 之间迁移时，`X:\下载` 一类 Windows 路径不能直接在 Linux 容器中使用。需要保留下载目录的只读挂载，并在副本配置中设置容器可访问的路径（例如 `/downloads`）；这属于跨平台迁移，不是只升级程序必须做的操作。

## 已验证的范围

- 网站回归覆盖旧库存关联、`bytes` / `size` 字段、目录、收藏、已购文件、配置和缓存保留，使用合成数据在临时目录验证。
- 2026-11-04 的一次 fnOS 实际升级核对了升级前后的 6,233 个数据文件，SHA-256 全部一致；原库存条目与本地商品数量保持不变。Beta 6 包含此次验证使用的在线扩展状态修复。
- 以上是已覆盖格式和一次实际部署的结果；自定义旧库应先备份，并在副本上验证自己的路径、格式和功能。
